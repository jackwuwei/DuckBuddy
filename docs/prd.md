## 1. 背景与目标

Microduck 是 Pollen Robotics 的双足小鸭机器人（15 个 XL330 舵机，2S 电池直供）。官方已经提供机器人端的全部能力（`robotd`、`btd`、`updaterd`、`mediad`），手机端目前只有最小可用的连接与视频验证。DuckBuddy 是 Microduck 的手机 App，不分中英文都叫这个名字。它要做的是**机器人的主界面**，而不是一个设置工具：用户在手机上就能完成添加机器人、驾驶、做动作、换策略、看状态和改网络。

**目标**

1. 新用户拿到鸭子后，5 分钟内能在手机上把它连上并开起来。
2. 平时驾驶只需要一个界面：看机器人视角、两个摇杆、几个动作按钮。
3. 官方的策略生态（官方 / 社区 / 本地策略、技能）在手机上可用，而且不会让用户把机器人弄坏后找不回来。
4. 机器人出问题时，用户能在状态页看出是哪里：电量、温度、站姿、哪个舵机偏了。

**非目标（本版本不做）**

- 账户、云端远程控制（官方 `account.*`、远程 WebRTC 仍在设计中）。
- 固件 / 系统更新界面（`update.*` 已有 API，另立需求）。
- 出厂重置、解绑手机（官方尚无 API）。
- 在手机上训练策略。

## 3. 设计原则

- **视觉统一官方品牌**：深色底 `#08080c`、Anton 全大写标题、DM Sans 正文、橙 `#FF7A2F` 主色，辅以黄 `#FFD23F`、粉 `#FF2FA8`、青 `#2FF0E6`、紫 `#9D87E8`；直角卡片、粗描边、硬投影（漫画分格风）。
- **少字**：每屏一个标题、一个主按钮；状态用颜色和图标表达，说明文字只在会出错的地方出现。
- **选中态统一**：所有"从一组里选一个"的地方（策略槽位、连接机器人、Wi-Fi 列表、添加鸭子）都用同一种选中样式：2 px 橙色描边 + 4 px 橙色硬投影。
- **主按钮统一**：橙底、黑描边、黄色硬投影；不可用时变灰。
- **标题栏统一**：左侧圆形返回键，Anton 标题，右侧带图标和文字的方形操作按钮。
- **横竖屏都支持**：横屏 844×390、竖屏 390×844 两套布局，功能一致。
- **默认中文**，支持英文。

## 5. 功能需求

优先级：P0 首发必须，P1 首发应有，P2 后续。

### 5.1 连接页

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| C-1 | 列出已添加过的机器人，每张卡片显示：头像、名字、连接方式（Wi-Fi / 蓝牙）、电压 | P0 |
| C-2 | 点卡片选中（统一选中样式），再点取消选中；默认选中上次用过的那只 | P0 |
| C-3 | 有选中时"连接"按钮可用，点击进入驾驶页；无选中时按钮置灰 | P0 |
| C-4 | 右上角"重新扫描" | P1 |
| C-5 | 虚线卡片"添加新鸭子"进入添加流程 | P0 |

验收：未选中任何机器人时无法进入驾驶；电压低于 6.6 V 显示为空电量（见 5.5）。

### 5.2 添加新鸭子（4 步）

顶部 4 个步骤图标：蓝牙 → 二维码 → Wi-Fi → 笔。当前步骤橙色，已完成青色打勾，未到灰色。每步左侧（竖屏为上方）是大图形，右侧是操作，底部一个主按钮。

| 步骤 | 交互 | 依据 / 规则 | 优先级 |
| --- | --- | --- | --- |
| 1 找鸭子 | 雷达动画；列出附近机器人，名字为 `duck-xxxx`，带信号强度条；已联网的机器人名字旁显示青色 Wi-Fi 图标。每行右侧"嘎"按钮让这只鸭子叫一声，用来在多只中认出手里这只。选中后"下一步" | 名字由 SoC 序列号派生，改名前就能区分；蓝牙广播里带 IPv4（`mobile-app.md` §7）；"identify" 需在认证前可用（官方待办） | P0 |
| 2 验证 | 点取景框扫描机器人身上的二维码；或粘贴 `md1:` 设置码点"验证"。成功显示"已验证"并自动进入下一步；格式不对显示粉色"设置码不对" | 生产机器人的设置码印成二维码，格式 `md1:<名字>:<64 位十六进制>`；出厂 PIN `000000` 由 App 静默发送，**不出现 PIN 输入页**（`mobile-app.md` §8） | P0 |
| 3 连 Wi-Fi | 选网络 → 输入密码（可显示明文）→ "连接" → "已联网 · IP" → "下一步"。**已联网的机器人跳过此步**，步骤条自动打勾 | 密码通过已认证的蓝牙加密通道发送（`net.connect`） | P0 |
| 4 起名字 | 名字预填为该机器人 ID，可改；下方小字显示不变的 ID。"完成"后图像换成张嘴的鸭子，显示"准备好了"和"开始驾驶" | 改名不改变 ID（`system.setName`） | P1 |

异常：

- 用户取消系统蓝牙配对弹窗 → 回到第 2 步，可重试（官方实测行为）。
- 设置码错误 → 不建立会话，修改后可在同一表单重试，无需重启机器人。
- Wi-Fi 连接失败 → 停留第 3 步，显示失败原因，可重选网络。

### 5.3 驾驶页（主界面）

**画面布局**

- 中间是机器人视角视频，**固定 9:16**。横屏居中 184×326；竖屏 244×434，左侧是摇杆模式列、右侧是动作列。
- 视频左上角"● LIVE 9:16"，右上角摄像头开关；视频底部叠加速度 / 角度读数，中心有准星，准星随头部朝向移动。
- 左上：机器人头像 + 状态点 + 状态文字（放松 / 坐着 / 站立 / 就绪 / 行走中），点击回连接页。
- 右上状态栏：信号、电池电压、**主控温度**（芯片图标），点击进入状态页；"策略"、"手柄按键"、电源键。
- 下方：左右两个虚拟摇杆，中间"启动 / 出发 / 停止"主键，左侧语音键。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| D-1 | **摇杆模式**（2 种）：行走（左摇杆移动、右摇杆转向）、头部（左摇杆转头 / 点头、右摇杆歪头）。读数随模式切换：行走显示 m/s 和 rad/s，头部显示转头 / 点头角度。原有的边走边看（与行走重复）和高度（官方尚无机身高度接口，§8）已去掉 | P0 |
| D-2 | **动作列**随模式变化。行走：坐下/站起、捡起、左踢、右踢、翻滚（按住连续翻）、更多。头部：回正、嘎嘎、欢呼、情绪 | P0 |
| D-3 | **情绪托盘**：点"情绪 / 更多"弹出：嘎嘎、点头、摇头、兴奋、自定义；自定义未绑定时提示去手柄按键里设置 | P1 |
| D-4 | **启动键**：未启动时为闪电"启动"→ 站立后为"出发"→ 行走中为"停止"。**长按 1.5 s 回到初始姿态**（环形进度） | P0 |
| D-5 | **电源键**：长按 2 s 休息、4 s 关机，环形进度在 2 s 后变红；短按提示"长按才会休息" | P0 |
| D-6 | 前置条件提示：未启动时按动作提示"请先按启动"；坐着时提示"请先站起"；声音类动作（嘎嘎、欢呼）不受限 | P0 |
| D-7 | **摄像头开关**：关闭后视频框显示"画面已关闭"，LIVE 变灰色 OFF，摇杆和动作不受影响；再点恢复 | P0 |
| D-8 | **语音控制**（见 5.4） | P1 |
| D-9 | 轮子模式下，A 键（坐/站）和 X 键在手柄上不生效（官方 `ROLLER_UNBOUND`），界面动作相应隐藏或置灰 | P1 |

### 5.4 语音控制

用户对着**手机麦克风**说话，由豆包「实时语音大模型 3.0（全双工版）」理解意思：鸭子**用动作和嘎嘎声回应**，**手机扬声器用一句很短的话播报执行状态和结果**（如"好，往前走"→"走完了"）。

**手势**（参考微信按住说话）：

1. **按住**麦克风键：画面变暗，顶部弹出黄色面板，显示"正在听"、跳动的音量条，以及**实时的语音识别结果**（逐字出现，带光标）。
2. 手指上方出现两个目标："取消"（左）和"发送"（右）。
3. **必须上划到"发送"再松开才执行**；上划到"取消"松开为取消；**原地松开不执行**，并提示"没有发送：上划到「发送」再松开"。
4. 划到"取消"时面板变粉、文字加删除线；划到"发送"时发送目标放大变橙。
5. 短按（不到 0.35 s）提示"按住麦克风说话"；系统中断触摸（如来电）视为取消。

**鸭子的回应**：

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| V-1 | 松手发送后，鸭子执行对应动作，同时发出**与意思相配的叫声**（见下表）；纯聊天（"你好呀""你真可爱"）只叫不动 | P1 |
| V-2 | 面板在发送后显示"鸭子在想…"，执行时把结果以提示条显示，例如 `"往前走两步" → 前进 2 秒 · 嘎`；播报的文字同步以一行小字显示在提示条下方 | P1 |
| V-2a | **语音播报**：手机扬声器播放豆包的回复，只说**状态和结果**，每句不超过 15 个字、不寒暄、不解释：开始执行时一句（"好，往前走"），执行完一句（"走完了" / "坐不下，我已经坐着了"）；纯聊天也只回一句短话 | P1 |
| V-2b | 播报**超过 4 秒自动淡出截断**；再次按住麦克风、按任意动作键或摇杆时立即停止播报 | P1 |
| V-2c | 播报跟随手机媒体音量；手机静音或设置里关闭"语音播报"时只显示文字 | P2 |
| V-3 | **取消就是什么都不做**：说话途中模型已决定的动作一律不执行、不叫、不播报 | P1 |
| V-4 | 做不到的事（未启动、坐着时走路、摔倒、没连上视频通道时要求移动）：鸭子发**警告叫声**，手机播报原因（"还没启动"），提示条同步显示，和按钮的前置条件一致（D-6） | P1 |
| V-5 | 听不懂或只听到杂音：鸭子发**疑问叫声**（尾音上扬），手机播报并提示"没听清，再说一次" | P1 |
| V-6 | 语音触发的移动**每次最多 5 秒**、速度不超过摇杆的一半，到时自动停；说"停"或按任意动作键立即停 | P1 |
| V-7 | 一次按住可以说一串（"站起来，往前走两步，再点个头"），按顺序执行 | P2 |
| V-7a | **没有设置豆包密钥时语音不可用**：麦克风键显示为灰色并带一个小钥匙角标；按下不录音，提示"先设置豆包密钥：状态 → 设置 → 语音"（见 5.9） | P1 |
| V-8 | 手机没联网时麦克风键置灰，提示"语音需要联网"；其他控制不受影响 | P1 |
| V-9 | 首次使用弹出说明：按住时的声音会上传到火山引擎识别，松手即停止；同意后才开启（系统麦克风权限之外的单独同意） | P1 |

**叫声与意思**（鸭子固件自带的 7 种叫声，每台鸭子的嗓音不同）：

| 叫声 | 听起来 | 用在 |
| --- | --- | --- |
| 嘎（chirp） | 普通的一声嘎 | 收到、好的、执行普通动作 |
| 嘎嘎（greet） | 醒来式的"嘎嘎" | 打招呼、叫它名字、站起来 |
| 嘎？（inquire） | 尾音上扬 | 没听懂、反问 |
| 咕（coo） | 软软的、带气声 | 被夸、撒娇、困了、坐下休息 |
| 呜哇——（wheee） | 一长串欢呼 | 开心、翻滚、转圈，随动作持续 |
| 嘎！（alarm） | 短促的大叫 | 做不到、拒绝、警告 |
| 笃（peck） | 低沉的一声 | 再见、去休息 |

**首批指令**：站起来、坐下、往前 / 往后走（可带"几步""一会儿"）、左转 / 右转、停下、点头、摇头、看左边 / 右边、踢一脚、捡东西、翻个跟头、叫一声、打招呼。说法不需要和列表一字不差，由模型理解。

前置条件与按钮一致（未启动、坐着时的限制同 D-6）。实现见技术方案 3.3。

### 5.5 状态页

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S-1 | **3D 机器人**：用官方仿真模型实时渲染当前姿态（关节角 + 躯干姿态），可拖动旋转、双击或按钮复位视角；渲染区域尽量大，文字不遮挡模型 | P0 |
| S-2 | **站姿**：站立 / 坐着 / 躺倒 / 不确定，配色区分，并显示躯干高度百分比和倾斜角、一句含义（如"启动时先用坐/站策略起身"）。判定规则沿用官方 `posture.rs`：倾斜 >45° 为躺倒；高度 <50% 为坐着、>80% 为站立、之间为不确定 | P0 |
| S-3 | **电池**电压（6.6 V 为空，8.2 V 为满；本机 2S 直供，约 7.9 V 属正常），**舵机最高温度**，**主控温度** | P0 |
| S-4 | **舵机位置**：按官方顺序列出 15 个舵机（左腿 20–24、头部 30–34、右腿 10–14）的实测角度；每行一条偏差条，表示实测与指令之差：<1° 灰、1–3° 黄、>3° 粉；悬停显示指令值与偏差；° / rad 切换 | P0 |
| S-5 | 右上角"网络"入口、"重启舵机"（对应官方 `robot.rebootMotors`，用于恢复过载锁定的舵机） | P1 |

### 5.7 策略页

概念（与官方一致，界面上用两排格子区分）：

- **槽位**：机器人平时由哪个策略驱动。双腿模式：行走、站立、坐/站、捡起；轮子模式：滑行、站立（不用，置灰）、坐/站、蹲下。
- **技能**：按一下才运行：左踢、右踢、翻滚（内置）以及用户添加的技能。
- **来源**：官方（橙点）、社区（紫点）、本地（浅色点）。只有官方策略能作为"恢复官方"的目标。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| P-1 | 顶部双腿 / 轮子切换；切换会先回到初始姿态，进行中锁定其他操作 | P0 |
| P-2 | 槽位格子显示当前在跑的策略名和来源色点；有更新显示黄色"新"角标；开机加载失败或模式冲突显示"!"角标 | P0 |

## 6. 全局交互规范

- **长按反馈**：所有长按操作（启动回位、电源休息/关机、语音）都有环形或面板进度，松手前可预知结果。
- **进行中锁定**：加载策略、切换模式、配网期间，相关按钮置灰，防止并发操作。
- **断线**：蓝牙断开时，App 静默重连、重新认证；期间显示状态，不弹窗打断。视频断开不影响蓝牙控制。
- **后台**：App 进入后台立即关闭视频和控制通道，机器人在约 0.6 s 内因"死人开关"停止（官方实测）。
- **语言**：默认中文，可切换英文；所有页面统一跟随。
- **无障碍**：所有图标按钮带 `aria-label`；选择类控件使用 radio 语义；文字与背景对比度 ≥ 4.5:1。

## 7. 安全与隐私

- 摄像头、控制和 Wi-Fi 密码只通过已认证的通道传输（蓝牙 Noise 加密会话 / 网关认证的 WebRTC）。
- 设置码只保存在系统安全存储，不写入普通配置文件。
- 社区策略默认不允许下载，开启后界面持续以紫色标识来源。
- 语音：只在按住麦克风期间采集并上传到火山引擎（豆包实时语音）识别，松手即停；首次使用单独征得同意；App 不保存录音。
- 豆包密钥由用户在设置里自行填写，只存在本机系统安全存储，只用于直连豆包（ST-8）。

| 指标 | 目标 |

## 9. 待确认事项

1. 摄像头真实分辨率和方向：官方实测为 1280×720，本设计按 9:16 竖幅显示，需确认摄像头安装方向或是否需要旋转 / 裁切。
2. 认证前的"让它叫一声"（identify）在官方仍是待办，首发若不可用，第 1 步改为按信号强度排序。
3. 每台机器人独立 PIN、解绑手机、出厂重置：官方无 API，暂不做。
4. "允许下载社区策略"的手机端写入接口需与官方确认（目前通过 `robotctl configure` 修改 `[policy] allow_community`）。
5. 轮子模式下关机时是否仍用坐/站策略坐下，官方文档未写明。
